- **Decision:** Adopt dynamic classification (Option B: Whitelist + Blacklist + DEX Liquidity Check) for Spam Detection, and auto-hide images for suspicious NFTs (Yes to Q2).
- **Rationale:** Checking DEX liquidity ensures newly created low-liquidity meme coins or static junk tokens are correctly classified as suspicious. Auto-hiding suspicious NFT images protects users from phishing URLs embedded in NFT metadata or visual assets.
- **Status:** Approved

### [2026-05-29] UTXO Consolidation Modes & Economic Safeguards
- **Decision:** Implement both "Smart Consolidate" and "Manual Selection" modes (Option B) for UTXO Consolidation, and add an "Economic Viability Alert" if Transaction Fee / Reclaimed ADA > 30% (Yes to Q2).
- **Rationale:** Provides simplicity for general users via Smart mode while giving power users control over specific UTXOs. The economic safeguard prevents users from losing ADA on inefficient consolidation transactions where fee costs outweigh the reclaimed ADA.
- **Status:** Approved

### [2026-05-29] Spam Token Treatment (Consolidation vs. Burning)
- **Decision:** Set "Spam Consolidation + Isolated Junk Box" as the default treatment for unburnable spam tokens. Offer "Full Burn" (sending the consolidated junk UTXO to an unspendable address) as an advanced option.
- **Rationale:** Most spam tokens on Cardano cannot be mathematically burned. Packing them into a single multi-asset UTXO ("Isolated Junk Box") minimizes the locked min-ADA to ~3-5 ADA, allowing the user to reclaim 90%+ of their locked ADA immediately by default. Users who prioritize a perfectly clean wallet can choose the advanced "Full Burn" option to completely discard the junk UTXO, sacrificing only the single consolidated min-ADA balance.
- **Status:** Approved

### [2026-05-29] False Positive Mitigations & User Control for Spam
- **Decision:** Implement safety mitigations for low-liquidity/new token false positives: 1. Do not auto-select suspicious assets for "Smart Consolidate", requiring manual opt-in. 2. Provide a local "Mark as Trusted" feature saved in LocalStorage. 3. Defer the "Community Feedback Loop / Report as Spam" feature to future phases (Out of Scope for MVP).
- **Rationale:** Prevents accidental consolidation/burning of newly launched or low-liquidity user assets. Keeps the MVP scope focused and practical, avoiding backend complexity for global reporting in v1.
- **Status:** Approved
